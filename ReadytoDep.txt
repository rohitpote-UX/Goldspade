4. DEPLOYMENT CHECKLIST — EVERYTHING YOU MUST UPDATE BEFORE DEPLOYING
================================================================================

Before deploying Goldspade to production (Vercel, Netlify, Docker, or VPS), complete 
the following MANDATORY configuration steps:

--------------------------------------------------------------------------------
STEP 1: CONFIGURE ENVIRONMENT VARIABLES
--------------------------------------------------------------------------------
Create or update your environment variables in your hosting provider's dashboard 
(e.g., Vercel Project Settings -> Environment Variables) or in `.env.local` for production:

1. `NEXT_PUBLIC_SITE_URL`
   - Description: The canonical live URL of your deployed domain.
   - Value: `https://www.goldspade.in` (or `https://your-domain.vercel.app`)
   - Purpose: Used by SEO metadata engine, OpenGraph cards, sitemaps, and canonical links.

2. `INQUIRY_EMAIL`
   - Description: The admin/notification email address that will receive project inquiries.
   - Value: `crohitpote17@gmail.com` (or `hello@goldspade.in`)
   - Purpose: All contact form submissions send formatted notification emails here.

3. EMAIL DISPATCH CONFIGURATION (Choose Option A OR Option B):

   OPTION A: Resend API (Recommended for Cloud / Serverless Deployments)
   - Obtain key from: https://resend.com
   - Set Variable: `RESEND_API_KEY=re_123456789...`
   - Note: In `lib/email/service.ts`, the default 'from' email is `onboarding@resend.dev`. 
     Once you verify your custom domain on Resend (e.g., `goldspade.in`), update the 
     'from' address in `lib/email/service.ts` to `inquiries@goldspade.in`.

   OPTION B: SMTP / Gmail Integration
   - Set Variables:
     `SMTP_HOST=smtp.gmail.com`
     `SMTP_PORT=465`
     `SMTP_USER=your_email@gmail.com`
     `SMTP_PASS=your_google_app_password`  (Generate via Google Account -> Security -> App Passwords)

4. DATABASE PERSISTENCE (Crucial Serverless Notice!):
   - By default, incoming form inquiries are appended to `data/inquiries.json`.
   - On Serverless Hosts (Vercel / Netlify / AWS Lambda), the local filesystem is 
     READ-ONLY or EPHEMERAL (erased between cold starts).
   - ACTION REQUIRED FOR PRODUCTION:
     a) Ensure `RESEND_API_KEY` or `SMTP_*` variables are set so you receive 
        every inquiry instantly via email.
     b) (Optional) If you want persistent database record storage, connect a database 
        (PostgreSQL, Supabase, or MongoDB) and set `DATABASE_URL`.

5. AUTHENTICATION PLACEHOLDERS (If activating Client Portal):
   - Set `NEXTAUTH_SECRET=your_random_long_secret_key`
   - Set `NEXTAUTH_URL=https://www.goldspade.in`


--------------------------------------------------------------------------------
STEP 2: DOMAIN & DNS CONFIGURATION
--------------------------------------------------------------------------------
- Add your custom domain in your host (Vercel -> Domains).
- Configure your DNS records at your registrar (Cloudflare, Namecheap, GoDaddy):
  - A Record: Points `@` to Vercel IP `76.76.21.21` (or your host IP).
  - CNAME Record: Points `www` to `cname.vercel-dns.com`.

--------------------------------------------------------------------------------
STEP 3: EMAIL DOMAIN SPF & DKIM RECORDS
--------------------------------------------------------------------------------
To prevent inquiry emails from going to spam:
- If using Resend: Add DNS records (MX, TXT, CNAME) provided by Resend dashboard.
- If using Gmail/Google Workspace: Ensure SPF (`v=spf1 include:_spf.google.com ~all`) 
  and DKIM records are configured in your DNS.

--------------------------------------------------------------------------------
STEP 4: VERIFY ALLOWED EXTERNAL ASSET DOMAINS
--------------------------------------------------------------------------------
If you add external images from new hosts, verify they are listed in `next.config.ts`:
```typescript
remotePatterns: [
  {
    protocol: "https",
    hostname: "images.unsplash.com",
  },
]
```

--------------------------------------------------------------------------------
STEP 5: PRE-DEPLOYMENT BUILD VERIFICATION
--------------------------------------------------------------------------------
Run a clean local build check to ensure zero TypeScript errors or lint issues:
```bash
npm run lint
npm run build
```

6. DEPLOYMENT GUIDES (STEP-BY-STEP)
================================================================================

--------------------------------------------------------------------------------
METHOD 1: DEPLOYING TO VERCEL (RECOMMENDED)
--------------------------------------------------------------------------------
Next.js is built by Vercel; deploying to Vercel provides seamless SSG, API routes, 
and edge caching out of the box.

1. Push your codebase to a Git repository (GitHub / GitLab / Bitbucket).
2. Go to https://vercel.com and click "Add New Project".
3. Import your `GoldSpade` repository.
4. Framework Preset will automatically detect `Next.js`.
5. Expand "Environment Variables" and add:
   - `NEXT_PUBLIC_SITE_URL` = `https://www.goldspade.in`
   - `INQUIRY_EMAIL` = `crohitpote17@gmail.com`
   - `RESEND_API_KEY` = `re_your_actual_key`
6. Click "Deploy".
7. Assign your domain under Project Settings -> Domains.

--------------------------------------------------------------------------------
METHOD 2: DEPLOYING TO DOCKER / CONTAINER
--------------------------------------------------------------------------------
Create a `Dockerfile` in the project root:
```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/package*.json ./
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["npm", "run", "start"]
```
Build and run the container:
```bash
docker build -t goldspade:latest .
docker run -p 3000:3000 --env-file .env.local goldspade:latest
```

--------------------------------------------------------------------------------
METHOD 3: DEPLOYING TO VPS (UBUNTU / PM2 / NGINX)
--------------------------------------------------------------------------------
1. SSH into VPS and clone repository.
2. Install Node.js (v20+) and PM2 (`npm install -g pm2`).
3. Install dependencies and build: `npm ci && npm run build`.
4. Start app with PM2:
   ```bash
   pm2 start npm --name "goldspade" -- run start
   pm2 save
   ```
5. Configure Nginx reverse proxy to forward traffic from port 80/443 to `http://localhost:3000`.

7. BACKEND API ARCHITECTURE & INQUIRY FLOW
================================================================================
Endpoint: `POST /api/inquiry`

Security & Protection Pipeline:
1. Rate Limiting: 
   - IP-based sliding window rate limiter (max 10 requests per 5 minutes per IP).
   - Prevents automated form spamming or denial-of-service attempts.
2. Honeypot Anti-Spam:
   - Hidden input field `_hp`.
   - Automated bots that fill this field trigger a silent approval response 
     without executing DB writes or sending emails.
3. Server-Side Validation:
   - Validates name (2-100 chars), email format (regex & length), overview (10-3000 chars), 
     and allowed budget strings (`< $10k`, `$10k - $25k`, `$25k - $50k`, `$50k+`).
4. Database Persistence (`lib/db/inquiries.ts`):
   - Generates unique ID (`inq_<timestamp>_<hash>`).
   - Atomically writes record to `data/inquiries.json`.
5. Email Dispatch (`lib/email/service.ts`):
   - Tries SMTP dispatch first (if `SMTP_USER` & `SMTP_PASS` exist).
   - Tries Resend API next (if `RESEND_API_KEY` exists).
   - Falls back to Development Console Log Mode if no credentials are configured.

9. TROUBLESHOOTING & COMMON FAQS
================================================================================
Q: Why do inquiry emails not arrive in dev mode?
A: By design, if no `RESEND_API_KEY` or `SMTP_PASS` is set, the server logs the email 
   to the terminal output and saves the record in `data/inquiries.json`. Add real keys 
   in `.env.local` to enable live sending.

Q: Will form submissions work on Vercel?
A: Yes! Form submissions send live emails via Resend or SMTP. However, since Vercel's 
   filesystem is ephemeral, `data/inquiries.json` resets on deployment redeploys. 
   Always rely on email notifications or connect a cloud database (PostgreSQL/Supabase).

Q: Build fails with "window is not defined"?
A: Ensure any browser-only library (like GSAP ScrollTrigger or Lenis) is guarded by 
   `typeof window !== 'undefined'` or used inside `useEffect`.
